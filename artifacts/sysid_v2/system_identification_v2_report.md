# Real2Sim 动力学系统辨识技术报告 (V2 重构版)

## 1. 任务背景与 V2 架构演进

在 Real2Sim V1 阶段，重点解决了实车 90° Settle 闭环起振与防套圈限位保护，并利用单条 Pass 2 数据对部分拟合参数进行了微调。然而，在深入诊断与专家审查后，确认了以下关键瓶颈：
- **采样率失步**：由于 UART 阻塞发送 5.73 ms 拖慢了 1 kHz 底盘主任务，导致实测采样周期为 28.0 ms (35.7 Hz)，而非配置的 20 ms (50 Hz)；
- **初始构型未严格对齐**：Settle 阶段力矩未克服静摩擦死区，固定 3 秒强行退出导致 Chirp 与 Square 绝对初态存在 $0.1\text{ rad}$ 偏差；
- **波形特化滤波与硬性锁死**：旧版在 Chirp 中特化启用了 5 Hz LPF 并在零速时人工钉死位置，违背了物理一致性；
- **自由长时域发散**：以 20 秒自由积分相关性为主目标，微小相位差在后期被无限放大。

针对上述问题，V2 架构贯彻**分层辨识、真实时间戳、实测力矩驱动、多步射击（Multiple Shooting）与留一轮交叉验证（Leave-One-Pass-Out）**的核心原则，建立物理可解释、具备强泛化能力的 Real2Sim 动力学基准。

## 2. 底层问题确诊与固件升级落地

### 2.1 遥测非阻塞 DMA 升级 (解决 35.7 Hz 采样失步)
- **诊断**：Page 61 包含 32 个单精度浮点数（132 字节帧），在 230400 波特率下占用总线 5.73 ms。旧版固件直接在 1 kHz 底盘主循环中调用 `HAL_UART_Transmit` 阻塞等待，导致主任务周期从 1.0 ms 恶化，实际采样周期变为 28.0 ms。
- **固件修复**：
  - 检查芯片硬件，确认 CubeMX 已配置 `USART10_TX` 的 DMA 通道 (`DMA1_Stream0` / `hdma_usart10_tx`)；
  - 重构 `src/modules/vofa_plus/vofa_plus.c` 与 `vofa_plus.h`，引入独立的平铺发送缓冲区 `dma_buf`；
  - 采用非阻塞调用 `HAL_UART_Transmit_DMA(&huart10, vofa->dma_buf, vofa->tx_length)`，若上一帧尚未传输完毕则直接返回 `HAL_BUSY` 跳过，彻底消除 CPU 阻塞；
  - 实车采样率将恢复至严格的 50.0 Hz (20.0 ms)。

### 2.2 Settle 摩擦前馈补偿与状态收敛判定 (解决初态不一致)
- **诊断**：五连杆腿在气弹簧 300 N 侧压顶推下存在静摩擦死区。旧版仅凭纯 PD 恢复力不足以克服死区，3 秒倒计时结束即进入激励，使电机停在假平衡点。
- **固件修复**：
  - 引入低速摩擦穿透前馈：$\tau_{\text{settle}} = K_p e - K_d v + \tau_{\text{ff}} \tanh(e / e_0)$，设定 $K_p = 4.0\text{ N}\cdot\text{m/rad}, K_d = 0.12\text{ N}\cdot\text{m/(rad/s)}, \tau_{\text{ff}} = 0.50\text{ N}\cdot\text{m}, e_0 = 0.05\text{ rad}$，限幅提升至 $1.40\text{ N}\cdot\text{m}$；
  - 建立严格收敛判定条件：
    1. 关节位置误差 $|e_i| < 0.03\text{ rad}$；
    2. 关节角速度 $|v_i| < 0.05\text{ rad/s}$；
    3. 连续保持稳定时间 $\ge 0.5\text{ s}$；
  - 增加 8.0 秒超时保护，超时则标记为 `SYSID_STATE_INVALID` / `SYSID_FAULT_TIMEOUT`，杜绝未收敛即强行起振。

## 3. 数据层规范与分层辨识设计

### 3.1 自动化切段与真实时间戳处理 (`sysid_data.py`)
- 利用 Channel 31 状态标签（Chirp: `3.0`，Square: `19.0`）自动寻找连续数据块，彻底废除依赖行号的硬切分；
- 计算真实动态微分时间步长 $dt$，仿真步进严格同步实车时间；
- 明确区分工况属性：
  - **Pass 1 (Cold Start)**：初次冷态启动，包含气弹簧密封与轴承初始突破卡滞（与 Pass 2 相关性仅 0.487），独立隔离；
  - **Pass 2 & Pass 3 (Warm Runs)**：热态重复性极高（Chirp 互相关 0.9902，Square 互相关 0.9987），作为物理参数辨识与交叉验证的标准数据集。

### 3.2 机械层输入与摩擦模型解耦 (`run_real2sim_v2.py`)
- **驱动输入**：机械层直接使用实车电机驱动器反馈力矩 `torq_r_j1`, `torq_r_j2`（Channel 20, 21），彻底剥离旧版 Chirp 特化的 5 Hz LPF 与人为假设；
- **摩擦物理模型**：删除直接将 `qpos` 锁死并清零 `qvel` 的伪物理判据，引入平滑 Stribeck 摩擦模型：
  $$\tau_f(v) = F_c \tanh\left(\frac{v}{v_\epsilon}\right) + (F_s - F_c) e^{-(v/v_s)^2} \tanh\left(\frac{v}{v_\epsilon}\right)$$
  与 MuJoCo 五连杆闭链力平衡、气弹簧张紧力及重力完全融合求解；
- **短视界多步射击 (Short-Horizon Multiple Shooting)**：采用 0.5s ~ 1.0s 滑动窗口滚动预测，消除 20s 长时域单点漂移，真实反映单步与多步动力学响应精度。

## 6. 后续工作与新数据采集建议

1. **烧录 V2 升级固件**：
   - 将 `build/CtrBoard-H7_ALL.bin` 烧录到底盘控制板；
   - 验证 DMA 发送是否将实车遥测帧率稳定在 50.0 Hz (20.0 ms)；
   - 验证 Settle 阶段是否在满足收敛条件后平滑、精准地进入起振。
2. **独立执行器高采样率辨识**：
   - 下一阶段建议配置精简高频遥测页（仅发 `time, cmd, torq, vel, Vbus` 6 个通道），将采样率提升至 $200 \sim 500\text{ Hz}$；
   - 单独拟合电机执行器的反电动势阻尼、纯通信延迟与电流环阶跃响应。
